# Добавление материалов

Материалы — это данные, а не код. Приложение само подхватывает любой пакет из `content/packs/`.

## Порядок работы

1. Прочитайте `docs/content-format.md`: там все поля, примеры и правила id. Схема: `src/core/content/schema.ts`.
2. Выберите место:
   - дополнение к базе — новый файл в `content/packs/osnova/data/` (например `c18-kultura.json`);
   - отдельный источник (книга, курс лекций, свои конспекты) — новый пакет:
     `pnpm content:new <id> "Название"`.
3. Прежде чем создавать сущность, проверьте, что её ещё нет: `rg -n '"id": "p-…"' content`,
   `rg -n 'Название' content`. Ссылайтесь на существующие id, а не создавайте дубликаты.
   Поиск по словам пропускает записи с другой транслитерацией id (`p-scherbatov`) и другой формой названия,
   поэтому каждый новый файл прогоняйте через `python3 scripts/qa/dups.py <файл>`: найденную запись дополняйте
   и ссылайтесь на неё, а не заводите вторую карточку.
4. id генерируйте командой `pnpm content:id <person|event|culture|term|source|deck|quiz|map> "Название"`.
5. Проверка файла: `pnpm content:check --file <путь>`. Проверка всего корпуса: `pnpm content:check`.
   Все ✖ исправить; ⚠ просмотреть. Статистика: `pnpm content:stats`.
6. Не меняйте код в `src/`: если формату не хватает поля, опишите это в PR, а не добавляйте поле в данные.

## Правила качества

- Пишите только проверяемые факты. Если источники расходятся, ставьте `confidence: "medium"`
  и делайте оговорку в `summary`. В `refs` указывайте источник: книгу и главу, лекцию, URL.
- Даты событий до 1918 года — по старому стилю, как в школьных учебниках.
- Длинные цитаты из современных книг класть нельзя. Выжимки своими словами допустимы.
- Картинки кладите в `<пакет>/images/`, до ~300 КБ, только разрешённые лицензии.
  Автора картинки укажите в `refs`.
- Материалы из платных книг помечайте в `pack.json` полем `"license": "personal"` и не публикуйте такой
  пакет в открытый доступ.

## Личные материалы без пересборки APK

`pnpm content:bundle <id>` собирает файл `dist-packs/<id>.stolypin.json`. Его импортируют на телефоне:
Профиль → Пакеты материалов → «Импортировать пакет».

## Самый надёжный путь (новое)

1. `pnpm content:add <event|person|culture|term|link> "Название" --year N [--wiki "Статья"]` — заготовка с правильным id,
   периодом и структурой в файле периода пакета.
2. Заполнить все `TODO` (проверка считает их ошибкой, так что недописанное не попадёт в приложение).
3. `pnpm content:check --file <файл>` → `pnpm content:check`; картинка — `scripts/media/wiki_images.py fetch/apply --ids <id>`.
Полное руководство: `docs/content-guide.md`.

## Дополнительно (обновлено)

- `short` у персоналии — самое известное имя («Иван Грозный», «Николай II»), отчество — в `aliases`.
- Правители: `reigns[].kind` (`head`, `regent`, `appanage`, `office`, `church`, `foreign`). Иностранные монархи,
  министры и патриархи не должны попадать на лестницу — проверьте `pnpm content:rulers`.
- Картинки событий появляются в «Галерее» и «Картине дня» автоматически; только свободные лицензии, webp ≤ 300 КБ.
- Книги: имя файла в `note` в «ёлочках» → `pnpm content:books`.
- Никаких упоминаний конкретного кружка/класса/преподавателя: материалы должны быть понятны любому ученику.

## Материалы для олимпиадников

Ориентир — финалы перечневых олимпиад: «Высшая проба», «Ломоносов», РАНХиГС, «Изумруд», РГГУ, ВсОШ.
Задания и ключи лежат на olimpiada.ru в PDF:
`https://tasks.olimpiada.ru/upload/files/tasks/<id>/<год начала>/<id>-<tasks|ans>-hist-<класс>-final-<гг-гг>.pdf`
(id: Высшая проба 147, Ломоносов 353, РГГУ 392, РАНХиГС 5285, Изумруд 5617). Текст — `pdftotext -layout`.

1. Варианты каждый год разные, поэтому ответы конкретного варианта в базу не переносим. Ищем повторяющиеся
   **типы заданий** и проверяем, закрыт ли тип целиком: работа с источником (летоисчисление, меры, денежный
   счёт, печати и гербы — `t-istoricheskaya-khronologiya`, урок `l-muscovy-vspomogatelnye-distsipliny`),
   атрибуция мемуаров и публицистики, картины и памятники, дипломатия, историография.
2. `python3 scripts/qa/olymp_gaps.py tasks.txt ans.txt` даёт зацепки: люди и названия, которых нет в базе.
   Прочитайте задание целиком: обычно за пропуском стоит целая тема, а не одна карточка.
3. Отрывок источника (`sources`) — только дословный текст: из задания олимпиады (в `refs` — олимпиада и год)
   или из публикации, которую вы видели. Нет текста — делайте карточку `culture` (автор, год, содержание) без цитаты.
4. Что уже закрыто, проверяйте по базе (`rg`, `dups.py`), а не по памяти: многие темы уже есть под другим названием.

## Картинки после бота

Коммит с `[media]` запускает бота, который подбирает картинки по полю `wiki`. Он часто ошибается: ставит
скульптуру или памятник вместо портрета, чужого человека с похожей фамилией, портрет автора вместо книги,
обложку или монету, на которой написан ответ. После его коммита:

1. Соберите новые картинки на один лист и просмотрите все:
   `git show --name-only --format= HEAD | grep webp` → `montage <файлы> -tile 7x -geometry 220x220+4+4 sheet.png`.
2. Неверная картинка: удалите `image` и `imageInfo` у записи, `git rm` файл и добавьте id в
   `scripts/media/overrides.json` со значением `null` (иначе бот вернёт её при следующем прогоне). Можно указать
   правильный файл Commons вместо `null`.
3. Картинка по теме, но не та, что следует из подписи (родственный предмет, позднейший памятник): исправьте
   `imageInfo.about`. Бот сохраняет ручную подпись, пока файл тот же.
4. Картинка, по которой ответ виден без знаний (надпись, обложка, памятная монета): у событий и памятников
   культуры поставьте `imageQuiz: false`. У персоналий такого поля нет: не-портрет человека удаляйте.
