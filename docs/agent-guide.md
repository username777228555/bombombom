# Руководство для агентов: введение в проект и добавление материалов

> **Коротко.** Материалы — это данные, а не код. Чтобы добавить событие, человека, произведение или термин:
> 1. `pnpm content:add <вид> "Название" --year 1698` — заготовка с правильным id и периодом;
> 2. заполните все `TODO` в указанном файле;
> 3. `pnpm content:check` — пока есть ошибки или `TODO`, CI не соберёт APK, так что недописанное не попадёт в приложение;
> 4. картинка — `python3 scripts/media/wiki_images.py fetch --ids <id>` и `apply --ids <id>`;
> 5. `pnpm build` и PR.
>
> Всё остальное (лента, граф, правители, карточки, тесты, игры, галерея) приложение построит само.

## 1. Что это за проект

**СТОЛЫПИНЪ** — офлайн-приложение для Android, чтобы готовиться к олимпиадам по истории России (ВсОШ и
перечневые олимпиады). Всё работает без интернета: база знаний встроена, прогресс хранится на телефоне.

- Стек: Svelte 5 (runes) + TypeScript + Vite, Capacitor 8 (APK), Dexie (IndexedDB), Cytoscape (граф),
  ts-fsrs (интервальные повторения), Zod (схема данных), foliate-js и PDF.js (читалка).
- Главный принцип: **знания лежат в JSON-пакетах `content/packs/`**, а экраны строят из них всё
  автоматически. Добавляя материал, код менять не нужно.
- Каждый PR проверяет CI: контент, типы, сборка APK. Релиз с APK выпускается веткой `release/vX.Y.Z`.

## 2. Карта репозитория

```
content/
  core/periods.json          11 периодов (id, годы, цвет, обложка-картина с подписью)
  packs/
    osnova/                  основной пакет
      pack.json              манифест (id, название, priority)
      data/01-ancient.json … 11-modern.json   материалы по периодам
      data/12-zhivopis.json, 13-muzyka-literatura-pamyatniki.json   тематические дополнения
      images/{persons,events,culture}/<id>.webp   картинки (с подписями в imageInfo)
    biblioteka/              «Книжная полка»: книги по периодам (sources)
  guides/reading.json        план подготовки: что прочитать, посмотреть, сделать
  schema/*.json              JSON Schema для автодополнения в редакторе (pnpm content:schema)
src/
  core/content/schema.ts     ЕДИНСТВЕННЫЙ источник правды о формате данных (Zod)
  core/content/validate.ts   проверки корпуса (ссылки, дубликаты, TODO, картинки…)
  core/content/kb.svelte.ts  база знаний: слияние пакетов, индексы, граф связей
  core/content/rulers.ts     кто считается правителем (reigns[].kind)
  modules/<name>/            экраны; module.ts регистрирует маршруты и плитки
  design/                    дизайн-система (docs/design.md)
scripts/
  content-add.ts             pnpm content:add — заготовка нового материала
  content-check.ts           pnpm content:check — проверка всех пакетов
  media/wiki_images.py       картинки с Wikimedia Commons (+ overrides.json для ручного выбора)
  qa/                        браузерные проверки (overlap_audit.py, smoke.py)
docs/                        architecture.md, content-format.md, design.md и этот файл
```

## 3. Как устроены данные

- **Пакет** — папка в `content/packs/` с `pack.json` и любыми `*.json` внутри `data/` (вложенность любая).
  Файлы и папки, начинающиеся с `_` или `.`, — черновики: приложение и проверка их пропускают.
- **Фрагмент** — один JSON-файл. В нём можно держать любые коллекции: `events`, `persons`, `culture`,
  `terms`, `links`, `sources`, `decks`, `quizzes`, `maps`.
- **id** уникальны во всём корпусе, латиницей, через дефис, с префиксом вида: событие `e-`, персоналия `p-`,
  культура `c-`, термин `t-`, источник `s-`. Не придумывайте id руками — их выдаёт `content:add`.
- **Период** выбирается по году (таблица в `docs/content-format.md`). Для культуры — период создания
  («Утро стрелецкой казни», 1881 → `c19`), а сюжет связывается с событием через `links`.
- Пакеты сливаются по `priority`: запись с тем же id в пакете с большим приоритетом заменяет исходную.

Что приложение делает с полями само:

| Поле | Где появляется |
|------|----------------|
| `events[]` (`year`, `importance`) | лента времени, «Ключевые даты» (importance 3), тесты, игры «Хронология», «Год-снайпер», «При ком это было?» |
| `persons[].reigns` (`kind: head/regent`) | «Правители», лента правителей, «Кто правил в … году?», сочинение |
| `persons[].hints` | игра «Кто я?» |
| `culture[].features` | карточки («Признаки: …») и страница произведения |
| `culture[].authors` / `authorName` + `image` | «Кто автор?» в «Галерее», вопросы на атрибуцию в тестах |
| `links[]`, `events[].persons` | граф связей, «Причины и следствия» в конструкторе сочинения |
| `image` + `imageInfo` | карточки, «Галерея», «Картина дня», аватары |
| `wiki` | скрипт картинок (в приложении не показывается) |
| `confidence: medium/low` | пометка «сверьте с учебником» |

## 4. Быстрый старт

```bash
pnpm install
pnpm dev                 # http://localhost:5173
pnpm check               # типы + проверка контента
pnpm build               # сборка веб-части
```

## 5. Добавляем материал: пошагово

### Шаг 0. Проверьте, что его ещё нет

```bash
grep -rni "стрелецк" content/packs          # поиск по названию
grep -rn '"id": "p-petr-i"' content/packs    # поиск по id
```

`content:add` тоже это проверит и не даст создать дубль. Лучше дополнить существующую запись: проверка
корпуса ругается на одинаковые названия под разными id.

### Шаг 1. Заготовка

```bash
pnpm content:add event   "Стрелецкий бунт 1698 года" --year 1698 --wiki "Стрелецкий бунт (1698)"
pnpm content:add person  "Артамон Матвеев" --born 1625 --died 1682
pnpm content:add culture "«Царевна Софья»" --year 1879 --kind painting --author "Илья Репин"
pnpm content:add term    "Посессионные крестьяне" --period c18
# связь между уже существующими id (здесь — созданными командами выше):
pnpm content:add link    c-tsarevna-sofya e-streletskiy-bunt-1698 --type related
```

Опции: `--pack <id>` (по умолчанию `osnova`), `--period <id>`, `--end <год>`, `--file <фрагмент.json>`,
`--importance 1|2|3`, `--dry` (показать, но не записывать), `--force` (только для тёзок). Нужен только id —
`pnpm content:id person "Иван III"`.

Команда не даст ошибиться: откажется создавать материал, если такое название (или краткое имя, или
вариант из `aliases`) уже есть, и откажется дублировать связь. Основной период персоналии она берёт по
годам деятельности (год рождения + 35), а не по году рождения: Пётр I (1672–1725) попадёт в XVIII век.

Запись попадает в файл периода пакета (например, `data/05-c18.json`); заполнить нужно все поля с `TODO`.

### Шаг 2. Заполните поля

**Событие** (`events`):

| Поле | Обязательно | Как заполнять |
|------|:-:|---------------|
| `title` | ✔ | как в учебнике: «Стрелецкий бунт», «Полтавская битва» |
| `year`, `period` | ✔ | год начала; период ставит `content:add` |
| `summary` | ✔ | 1–3 предложения: суть и значение, своими словами |
| `month`, `day` | | до 1918 года — по старому стилю, как в учебниках |
| `endYear` | | для войн и реформ |
| `importance` | | 3 — обязательно знать, 2 — важно, 1 — деталь для финала |
| `tags` | | `politics`, `war`, `reform`, `economy`, `society`, `church`, `culture`, `foreign`, `uprising`, `law`, `science`, `dynasty`, `territory` |
| `persons` | | id участников (связи в графе появятся сами) |
| `details`, `place`, `refs` | | подробный текст (абзацы через `\n\n`), место, источник («Учебник Орлова, гл. 5») |
| `wiki` | | название статьи русской Википедии — для картинки |
| `confidence` | | `medium`/`low`, если дата или деталь спорная |

**Персоналия** (`persons`): `name` (полное имя), `short` — **известное имя без отчества** («Дмитрий
Донской», «Николай II»), отчество и другие формы — в `aliases`; `born`/`died` (год или `null`), `periods`
(первый — основной), `role` одной строкой, `summary`, `hints` (3–5 подсказок **без имени**, от трудной к
лёгкой), `tags` (`ruler`, `statesman`, `military`, `church`, `culture`, `science`, `revolutionary`,
`reformer`, `writer`, `artist`, `historian`, `diplomat`, `rebel`, `explorer`, `entrepreneur`).
Должности — `reigns: [{ "title": "Царь всея Руси", "from": 1613, "to": 1645 }]`. Вид должности обычно
угадывается по титулу; если титул необычный, укажите `kind`: `head` (глава государства), `regent`,
`appanage` (удельный князь), `office` (министр, наместник), `church` (патриарх, митрополит), `foreign`
(иностранный монарх). На лестницу правителей попадают только `head` и `regent` — проверьте `pnpm content:rulers`.

**Культура** (`culture`): `title`, `kind` (`painting`, `icon`, `architecture`, `literature`, `music`,
`sculpture`, `theatre`, `cinema`, `science`, `applied`, `document`, `chronicle`), `year` (+ `endYear`),
`authorName` или `authors` (id персоналий), `summary`, `features` — 2–4 признака, по которым произведение
узнают на олимпиаде. Пример — `data/12-zhivopis.json`.

**Термин** (`terms`): `term`, `definition`, `periods`, `related` (id связанных материалов).

**Книга** «Книжной полки»: `sources` в `content/packs/biblioteka/data/`, точное имя файла — в `note` в
«ёлочках», затем `pnpm content:books`.

### Шаг 3. Связи

`links` — связи графа: `{ "from": "…", "to": "…", "type": "cause" }`. Типы: `cause` (привело к),
`part-of` (часть), `participant`, `leader`, `author`, `successor`, `parent`, `influence`, симметричные —
`spouse`, `ally`, `opponent`, `related`. Участников события достаточно указать в `events[].persons`.
Картину на исторический сюжет свяжите с событием: `{ "from": "c-…", "to": "e-…", "type": "related" }`.

### Шаг 4. Картинка

1. Укажите `wiki` — название статьи русской Википедии.
2. `python3 scripts/media/wiki_images.py fetch --ids <id>` → `apply --ids <id>` (нужны `requests`,
   `pillow`, `opencv-python`). Скрипт возьмёт главную картинку статьи, проверит свободную лицензию, обрежет
   портрет по лицу и запишет `image` + `imageInfo` (только русские подписи).
3. Скрипт выбрал не то (фото храма вместо фресок, карту вместо картины)? Найдите нужный файл на
   commons.wikimedia.org и пропишите его в `scripts/media/overrides.json`: `"c-…": "Имя файла.jpg"`
   (`null` — картинка не нужна), затем повторите шаг 2 с `--refresh`.
4. Без интернета или вручную: webp до ~300 КБ в `images/<вид>/<id>.webp`, в `imageInfo` — `title`,
   `author`, `date`, `about`, `license` по-русски. Только общественное достояние или свободные лицензии.

В CI то же самое делает workflow «Media»: коммит с `[media]` в сообщении в ветку `gumball/**` или `media/**`.

### Шаг 5. Проверка

```bash
pnpm content:check --file content/packs/osnova/data/05-c18.json   # только ваш файл
pnpm content:check                                                # весь корпус
pnpm content:rulers        # если трогали правителей
pnpm content:books         # если трогали книги
pnpm build
```

Ошибки (✖) обязательно исправить, предупреждения (⚠) — прочитать. Затем коммит и PR — CI проверит всё ещё раз
и соберёт APK.

## 6. Правила качества

- Факты сверяйте с учебником; сомнительное помечайте `confidence: "medium"` или `"low"`.
- Тексты — своими словами, без длинных цитат из современных книг.
- Даты до 1918 года (`month`, `day`) — по старому стилю.
- Подписи к картинкам — только по-русски; ники фотографов и английские названия файлов не пишем.
- Ссылки на Википедию в `refs` не кладём: название статьи — в поле `wiki`.
- Никаких упоминаний конкретного кружка, класса или преподавателя.
- Не пишите «в Украине» — в проекте принято «в Малороссии».
- Картинки — только общественное достояние или свободные лицензии (CC0, CC BY, CC BY-SA).

## 7. Частые сообщения `content:check`

| Сообщение | Что сделать |
|-----------|-------------|
| `не заполнено («TODO…»)` | допишите значение или удалите необязательное поле |
| `повтор id «…»` | id уже занят — используйте существующую запись или другой id (`content:add` подберёт сам) |
| `ссылка на несуществующий id «…»` | опечатка в id или материал ещё не добавлен (`grep -rn '"id": "…"' content`) |
| `неизвестный период «…»` | id периода из таблицы в `docs/content-format.md` |
| `год … далеко за рамками периода` | проверьте год или период |
| `похоже на дубликат «…»` | такое название уже есть — дополните ту запись |
| `ссылка на Википедию: перенесите … в поле wiki` | уберите URL из `refs`, впишите название статьи в `wiki` |
| `short — это известное имя без отчества` | `short: "Дмитрий Донской"`, полное имя — в `aliases` |
| `подсказка выдаёт имя` | перепишите подсказку без имени и фамилии |
| `файл «images/…» не найден` | положите картинку или уберите `image` |
| `у картинки нет сведений (imageInfo)` | запустите скрипт картинок или заполните `imageInfo` вручную |
| `невалидный JSON` | лишняя/пропущенная запятая или кавычка — проще всего переписать через `content:add` |
| `Invalid option: expected one of …` | значение не из списка (тег, вид культуры, тип связи) — выберите из перечисленных |
| `Invalid input: expected …, received undefined` | не хватает обязательного поля (например, `summary`) |
| `Unrecognized key: "…"` | лишнее или опечатанное поле (`sumary` вместо `summary`) — сверьтесь с таблицами выше |

## 8. Если нужно больше, чем данные

- Новый курс или набор материалов целиком — отдельный пакет: `pnpm content:new lekcii-mgu "Лекции МГУ"`.
- Новый экран или игра — папка в `src/modules/` и `module.ts` (пример: `src/modules/study/module.ts`).
- Новый тип вопроса, орден, тема — рецепты в `AGENTS.md` и `docs/architecture.md`.
- Дизайн, анимации, SVG — `docs/design.md`.

## 9. Перед PR и выпуск версии

- `pnpm check && pnpm content:books && pnpm build`; если трогали вёрстку, ленту или граф — `scripts/qa/`.
- Выпуск APK: поднимите `version` в `package.json`, создайте ветку `release/vX.Y.Z` — CI опубликует релиз.
