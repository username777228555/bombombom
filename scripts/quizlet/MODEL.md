# Задания импорта Quizlet: инструкция для модели

Ты помогаешь перенести карточки из Quizlet в приложение по истории России. Работаешь только с файлами заданий.
Читать базу, PDF, код и другие задания не нужно: всё, что нужно для ответа, есть в самом задании.

## Порядок

1. Открой задание `import/quizlet/work/tasks/<имя>.json`.
2. Запиши ответ в `import/quizlet/work/answers/<то же имя>.json`. Это объект `{ "<card>": ответ, … }` с ключом
   **для каждой** карточки задания (поле `card`). Если сказать нечего, пиши `null`.
3. Запусти `pnpm -s quizlet check` и исправь всё, что он покажет, пока у файла не будет ✓.
4. Не меняй задания, код и другие файлы.

Общие правила:

- Только по-русски, без латиницы.
- Не выдумывай. Если не уверен, ставь `null`. В заданиях `enrich` вместо этого пиши `doubt`.
- В карточках Quizlet бывают ошибки. Если карточка расходится со статьёй базы, верь базе, а расхождение опиши в `doubt`.

<a id="link"></a>
## link: к какой статье относится карточка

В задании есть `front` и `back` карточки и `candidates`: до пяти статей базы, похожих по названию.
Ответ — `id` статьи, о которой карточка, или `null`, если ни одна не подходит.

- Подходит статья о том же самом или о целом, частью которого карточка является. Например, мирный договор
  относится к войне, которую он завершил, а отдельный указ — к реформе.
- Если статьи называются одинаково, выбирай по годам и смыслу.
- Одно общее слово («реформа», «сражение», «мир») не повод связывать. В таком случае ответ `null`.

```json
{
  "vnutrennyaya-politika-ekateriny-ii-4": "e-zhalovannye-gramoty",
  "russko-tureckie-voyny-xviii-veka-4": null
}
```

<a id="enrich"></a>
## enrich: чем карточка дополняет статью

В задании есть:

- карточка;
- `entity` — статья базы: `summary`, `details`, `aliases`, а в `allowed` перечислены поля, которые можно дополнять;
- `newFacts` — годы и имена из карточки, которых в статье нет.

Ответ `null`, если карточка не добавляет ничего верного и важного. Так бывает чаще всего. Иначе ответ — объект,
в котором только поля из `allowed` и, если нужно, `doubt`:

| поле | что это |
|------|---------|
| `aliases` | 1–3 других названия или имени, под которыми это знают. Инициалы и порядок слов учитываются сами, их не добавляй |
| `hints` | 1–3 подсказки для игры «Кто я?»: короткий факт без имени самого человека, до 160 символов |
| `features` | 1–3 признака произведения, по которым его узнают, до 160 символов |
| `details` | 1–2 предложения, до 400 символов, с новым фактом. Их допишут в конец статьи, поэтому пиши своими словами и в стиле статьи, без «в карточке сказано» |
| `doubt` | карточка противоречит статье (другой год, другой автор): кратко, что не сходится. Само противоречие в другие поля не пиши |

Не повторяй то, что уже есть в `summary` и `details`.

```json
{
  "vnutrennyaya-politika-ekateriny-ii-6": { "hints": ["Донской казак, выдававший себя за чудом спасшегося императора Петра III."] },
  "vnutrennyaya-politika-ekateriny-ii-1": { "doubt": "В карточке роспуск в 1769 году, в статье — в 1768." },
  "vnutrennyaya-politika-ekateriny-ii-9": null
}
```

<a id="new"></a>
## new: карточки, которых нет в базе

В задании карточки, для которых в базе не нашлось статьи. Ответ `null`, если карточка — деталь, определение
внутри темы или мусор и отдельной статьи не заслуживает. Иначе ответ — `{ "kind", "title", "year" }`:

- `kind`: `event` — событие, `person` — человек, `term` — понятие, `culture` — произведение или памятник;
- `title` — как назвали бы статью в учебнике:
  - событие: «Чесменское сражение»;
  - человек полностью: «Александр Васильевич Суворов»;
  - понятие: «Секуляризация»;
  - произведение в кавычках: «Медный всадник»;
- `year` — год события, рождения человека или создания произведения. Если точно не знаешь, не пиши поле.

```json
{
  "russko-tureckie-voyny-xviii-veka-4": { "kind": "event", "title": "Чесменское сражение", "year": 1770 },
  "vnutrennyaya-politika-ekateriny-ii-7": null
}
```
