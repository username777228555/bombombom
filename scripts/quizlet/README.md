# Импорт Quizlet: регламент

Распечатка наборов Quizlet в PDF превращается в колоды приложения (`content/packs/quizlet/`) со ссылками на статьи
базы, а новые факты из карточек дописываются в базу. Почти всё делают скрипты. Модель отвечает только на маленькие
задания, в которых уже собрано всё нужное: она не читает ни базу целиком, ни PDF, ни картинки. Поэтому задания
можно отдать Haiku или Sonnet.

| шаг | кто | команда |
|-----|-----|---------|
| 1. PDF → карточки и картинки | скрипт | `python3 scripts/quizlet/extract.py import/quizlet/*.pdf` |
| 2. сопоставление с базой | скрипт | `pnpm quizlet match` |
| 3. задания пачками | скрипт | `pnpm quizlet tasks` |
| 4. ответы на задания | Haiku (`link`, `new`), Sonnet (`enrich`) | по `scripts/quizlet/MODEL.md`, проверка `pnpm quizlet check` |
| 5. колоды и дополнения базы | скрипт | `pnpm quizlet apply` → `pnpm check` |
| 6. просмотр | сильная модель или человек | `import/quizlet/work/review.md`, выборочно `git diff content/packs/osnova` |

## 1. Где взять PDF

Положите распечатку в репозиторий одним из двух способов:

- файл до 25 МБ — в папку `import/quizlet/` через github.com («Add file → Upload files»);
- файл больше — в релиз с тегом **`import`**, не `books`: из релиза `books` приложение берёт книги.
  Скачать файл в контейнер можно так:
  `curl -L -o import/quizlet/quizlet.pdf https://github.com/username777228555/bombombom/releases/download/import/<файл>`.

Печатать нужно сам набор, то есть список «термин — определение» с картинками. Тесты Quizlet не нужны: приложение
строит вопросы по карточкам само.

## 2. Извлечение

`extract.py` печатает сводку по каждому набору: сколько карточек нашлось и сколько их по заголовку Quizlet
(«Термины в этом модуле (N)»). Если числа совпали, переходите к шагу 3.

Если не совпали, значит, у распечатки другая раскладка. Этот шаг правится один раз, и только здесь может
понадобиться сильная модель:

- `extract.py file.pdf --dump 3` — строки страницы 3 с координатами, кеглем и жирностью;
- `extract.py file.pdf --preview 3` — картинка страницы с найденными строками и рисунками в `work/preview/`.

По ним настраивается разбор в `extract.py`: колонки, линии таблицы, `--row-gap`. Затем запустите извлечение снова.
Имена картинок — это хэш содержимого, поэтому при повторном извлечении они не меняются.

## 3–4. Задания для модели

`pnpm quizlet match` связывает карточку со статьёй базы сам, если имя совпало точно. Тёзок он различает по году.
Остальные карточки `pnpm quizlet tasks` раскладывает по заданиям в `import/quizlet/work/tasks/`:

| задание | что решает | пачка |
|---------|-----------|-------|
| `link-NNN` | к какой из 2–5 похожих статей относится карточка | 40 |
| `enrich-NNN` | что нового и верного карточка добавляет к статье. Попадают только карточки с годами и именами, которых в статье нет | 20 |
| `new-NNN` | заслуживает ли карточка без статьи отдельного материала | 50 |

`enrich` и `new` появляются после ответов на `link`, поэтому `tasks` нужно запустить ещё раз.

Промпт для субагента: одно-три задания на субагента, модель Haiku или Sonnet.

> Рабочая папка: /home/user/bombombom. Прочитай scripts/quizlet/MODEL.md и выполни задания
> import/quizlet/work/tasks/link-001.json, link-002.json. Ответы запиши в import/quizlet/work/answers/ под теми же
> именами. После каждого файла запусти `pnpm -s quizlet check` и исправляй ошибки, пока файл не будет ✓.
> Ничего больше не читай и не меняй. В конце одной строкой: сколько карточек связал, сколько null.

Можно и без субагентов: откройте новую сессию на Sonnet и напишите «выполни задания Quizlet по
scripts/quizlet/MODEL.md». `pnpm quizlet status` покажет, что осталось.

Задания и ответы коммитятся после каждой пачки, так работу можно продолжить в другой сессии. `work/img/` и
`work/preview/` в git не попадают, их восстанавливает `extract.py`.

## 5–6. Применение и проверка

`pnpm quizlet apply` делает три вещи:

- пишет колоды в `content/packs/quizlet/`: один набор — одна колода, картинки копируются, у карточки есть
  `entity` (ссылка «Статья →»);
- дописывает в базу принятые дополнения: `aliases`, `hints`, `features`, `details`. Уже имеющееся пропускается,
  поэтому команду можно запускать повторно;
- составляет `work/review.md`: расхождения карточек с базой (в базу они не вносятся), кандидатов в новые
  материалы (`work/backlog.json`) и пропущенное.

Потом запустите `pnpm check`, просмотрите `review.md` и выборочно `git diff content/packs/osnova`.

Новые статьи по `backlog.json` пока не создаются автоматически: для этого есть `pnpm content:add`.
